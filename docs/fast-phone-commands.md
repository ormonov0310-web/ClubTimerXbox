# Быстрые команды телефона

Эта схема является стандартом для всех новых команд Club Timer Xbox,
отправляемых из Android-приложения владельца на ПК.

## Обязательный поток

1. Телефон сохраняет `updatedAtUnixMs` текущего снимка выбранного клуба.
2. Телефон создаёт команду в `clubs/{clubId}/commands/{commandId}`.
3. ПК применяет изменение локально.
4. До установки статуса `applied` ПК публикует обновлённый `/current`.
5. Телефон каждые 500 мс проверяет:
   - изменение `/current/updatedAtUnixMs`;
   - статус команды с `Cache-Control: no-cache` и уникальным `_ts`.
6. Как только ревизия снимка выросла, телефон читает свежий `/current`
   выбранного клуба и обновляет текущий экран.

Не нужно после успешной команды отправлять дополнительную
`RefreshCurrentData`: ПК уже опубликовал полный снимок перед `applied`.

## Требования к новым функциям

- Обычные команды Android должны использовать общий `sendCommand`.
- Обработчик ПК должен вызывать `MarkCommandApplied` с
  `pushCurrentState: true`.
- Ошибка должна завершаться через `MarkCommandError`; телефон не должен
  показывать успех до новой ревизии или статуса `applied`.
- Чтение после команды выполняется только для выбранного клуба.
- Ввод пользователя нельзя перерисовывать фоновыми обновлениями.
- Переходы между экранами используют кэш и не создают команду ПК каждый раз.
- Автоматический полный снимок допускается не чаще одного раза в 2 минуты.
- Ручная кнопка обновления всегда может запросить точный снимок у ПК.

## Проверено

- Сверка безнала: около 3,5-4 секунд.
- Добавление расхода: около 4 секунд.
- Выдача зарплаты: быстрый отклик подтверждён.
- Внесение корректировки: быстрый отклик подтверждён.
- Переходы `Касса -> Отчёт -> Работники`: 0 лишних команд ПК.

Если новая команда заметно медленнее, сначала сравнить `createdAt`,
`appliedAt` и `updatedAtUnixMs`, а не увеличивать частоту постоянной
синхронизации.
