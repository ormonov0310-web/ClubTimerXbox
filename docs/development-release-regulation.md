# Регламент разработки и выпуска

## Android-приложение владельца

Любое изменение Android-части считается завершённым только после полного цикла:

1. собрать APK;
2. прогнать доступные проверки и Android lint;
3. установить APK через ADB поверх текущего приложения с сохранением данных;
4. запустить установленное приложение;
5. проверить версию, активный экран и отсутствие ошибки запуска.

Если телефон подключён к ПК, отдельное разрешение на пересборку и установку APK
не требуется.

## ПК-приложение

Локальные изменения и тестовые сборки разрешены в процессе разработки.
Публичный пакет обновления, тег, GitHub Release и Firebase-манифест создаются
только после точной команды владельца выпустить обновление.

После исправления найденной ошибки нужно спросить:

> Это все изменения для следующего обновления или есть ещё что добавить?

Положительный ответ на этот вопрос не заменяет отдельную точную команду на
публичный выпуск.
